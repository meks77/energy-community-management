= Aufgabenliste: Energy Community Management

== Phase 1: Fundament & Domänenmodell (Core)
1. [ ] Kernentitäten (Mitglied, Rechnung, Zahlung, Buchung) in Kotlin gemäß Clean Architecture Prinzipien definieren. (Mitglied und Rechnung implementiert, inklusive Tests für Duplikate)
2. [ ] Event-Sourcing-Infrastruktur (z. B. Axonframework) implementieren oder integrieren.
3. [ ] Strikte Trennung von Drittanbieter-Bibliotheken von der Domänenschicht sicherstellen.
4. [ ] Verschlüsselte Speicherung für sensible Finanzdaten implementieren.
5. [ ] Mechanismen für die Datensicherung (Backup) entwickeln.
6. [ ] Mechanismen für den sicheren Datenaustausch zwischen Benutzern (Multi-User-Fähigkeit) implementieren.

== Phase 2: Datenimport & Integration
7. [ ] Adapter für Energy-Family Mitgliederexporte entwickeln.
8. [ ] Adapter für Energy-Family Rechnungsexporte entwickeln.
9. [ ] Flexible Parser für Bankkonto-CSV-Exporte implementieren.
10. [ ] Logik zur Prüfung der Referenzierbarkeit über Zahlungsreferenz oder Anweiser implementieren.
11. [ ] Mapping-Algorithmen zur Zuordnung von Zahlungen zu Rechnungen und Mitgliedern entwickeln.
12. [ ] Behandlung nicht zuordenbarer Zahlungen (manueller Eingriffsprozess) implementieren.

== Phase 3: Funktionale Module (Features)
13. [ ] Modul Zahlungs-Clearing implementieren: Automatischer Abgleich von Bankeinträgen mit offenen Posten in Energy-Family.
14. [ ] Modul Umsatzsteuererklärung implementieren: Aggregation der Einnahmen basierend auf Ist-Versteuerung.
15. [ ] Trennung von geschäftlichen vs. privaten Entitäten im Umsatzsteuermodul implementieren.
16. [ ] XML-Export für Finanz-Online (Umsatzsteuer) implementieren.
17. [ ] Modul Saldenliste implementieren: Übersicht über Einnahmen, Ausgaben und Salden (Gewinn/Verlust) erstellen.
18. [ ] Modul Zahlungserinnerungen implementieren: Automatisierter E-Mail-Versand für überfällige Rechnungen basierend auf Clearing-Daten.

== Phase 4: Validierung & Spezifikation
19. [ ] Framework für ausführbare Spezifikationen (z. B. Concordion) einrichten.
20. [ ] Automatisierte Tests für alle Spezifikationen implementieren.
21. [ ] Clean Code & Architektur-Audit durchführen, um die Einhaltung von Uncle Bobs Clean Architecture sicherzustellen.
22. [ ] Verifizieren, dass die gesamte Domänenlogik unabhängig von technischen Details (Frameworks, Parser, UI) bleibt.
